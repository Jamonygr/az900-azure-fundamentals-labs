# Security reporting

Do not post credentials, tokens, tenant IDs, or subscription details in public issues. For a sensitive vulnerability, use GitHub's private vulnerability reporting on this repository when available. Otherwise report the issue through GitHub support or contact the maintainer through an existing private channel.

For documentation defects without sensitive information, open an issue describing the affected lab, the unsafe behavior, and a redacted example. Revoke exposed credentials promptly through the relevant provider.

Scripts limit writes to explicitly owned lab resource groups. Reviews and offline mocks reduce risk but cannot guarantee Azure policy, permissions, or regional availability in your environment.
